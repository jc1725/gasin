## 운영 원칙

CSV 업로드와 Drive 동기화는 후보 행을 `productCandidates`에 저장하거나 갱신할 뿐이다. 후보 상태가 `pending`인 동안에는 쿠팡 API를 호출하지 않는다. 사용자가 이미 입력한 쿠팡 URL을 명시적으로 ‘추적 대기’로 보낼 때만 기존 수동 링크 등록 로직이 실행되며, 이 경우에도 즉시 외부 조회를 하지 않고 `waiting` 상태로 보관한다.

첫 Drive 동기화는 사용자의 연결 Drive 폴더에 `gasyn-candidates.csv` 템플릿을 한 번 생성하고 0건 성공으로 종료한다. 사용자가 상품 행을 추가한 뒤 다음 동기화에서 후보를 저장한다. 실제 개인 Drive에 작성된 CSV를 읽어 저장한 운영 증거와 `drive` 실행 로그는 별도 검증 항목으로 남겨 둔다.

## 실제 개인 Drive 운영 검증

2026-08-16 05:09:42 UTC에 연결된 개인 Drive 폴더에 `gasyn-candidates.csv` 템플릿이 생성되었고, 이후 CP949로 저장된 한국어 후보 CSV를 다시 동기화했다. 최신 `drive` 실행은 2026-08-16 05:58:55~05:58:56 UTC에 `success`, `processedCount=1`로 완료되었으며 세부 기록은 `candidate CSV loaded: 1 rows; Coupang API not called`이다. 운영 DB에는 `userId=1620001`, `source=drive_csv`인 후보 1건이 저장되었다.

초기 CP949 파일은 서버가 UTF-8로만 읽던 배포에서 `상품명` 헤더를 찾지 못해 실패했지만, 공통 `euc-kr` 재시도 디코더를 배포한 뒤 동일 파일이 정상 처리되었다. 화면에 남은 빨간 오류 문구는 이전 실패 실행의 상태 메시지이며, 최신 동기화 결과는 성공이다.

테스트 기준은 전체 30개 테스트 파일, 67개 통과, 4개 스킵 및 `pnpm check` 통과다.

## 후보 편집·삭제 및 피드백 검증

2026-08-16 기준 후보 보관함의 `update`·`remove` tRPC 경로는 로그인 사용자 ID를 DB 헬퍼에 함께 전달하여 사용자 소유 후보만 수정·삭제한다. `server/candidates.noCoupangCall.test.ts`에서 두 경로 모두 외부 `fetch`를 호출하지 않는 것을 검증했고, `client/src/lib/candidateSyncFeedback.test.ts`에서 새 CSV·Drive 동기화 전에 두 mutation의 이전 오류 상태를 함께 초기화하는 동작과 성공·안내 문구를 검증했다. 전체 검증 결과는 31개 테스트 파일 통과, 2개 스킵, 71개 테스트 통과, 4개 스킵 및 `pnpm check` 통과다.

## 딥링크 시점 정책

후보를 ‘추적 대기’로 보내는 시점에는 `createManualLinkTrack`가 이미 저장된 상품과 연결하거나 `waiting` 상태로 등록할 뿐, 딥링크 API를 즉시 호출하지 않는다. 이후 승인된 정기 처리 경로에서 딥링크가 없는 상품만 생성 대상으로 삼고, 이미 `link.coupang.com` 제휴 링크인 값은 재전송하지 않고 저장 링크를 재사용한다. 따라서 화면 안내는 “딥링크가 없으면 다음 승인 API 안전 처리에서 생성하며, 이미 저장된 제휴 링크는 재사용”으로 정정했다.

## GoldBox 수정 후 운영 상태

2026-08-16T00:07:52Z에 실행된 GoldBox 작업은 수정 배포 전 실행으로, 500 응답과 `Coupang API error 400: url convert failed`를 남겼다. 딥링크 안전성 수정 버전 `e88e06b0` 이후의 GoldBox 다음 실행은 2026-08-16T12:00:00Z 예정이며, 현재 시각 2026-08-16T06:18:59Z 기준 아직 실행 전이다. 따라서 수정 후 GoldBox의 신규 2xx 콜백과 `syncRuns status=success`는 미확정으로 유지하며, 실행 후에만 관련 TODO를 완료 처리한다.

## 후속 운영 상태 정정

이 문서의 과거 대기 메모는 당시 검증 시점의 상태를 보존한다. 이후 운영에서 Google Cloud Console의 콜백 등록을 저장했고, 운영 도메인의 개인 Google OAuth 로그인·콜백 및 CP949 후보 CSV 동기화까지 성공했다. 현재 미확정인 항목은 딥링크 수정 배포 후 첫 GoldBox 실행의 2xx 콜백과 `syncRuns success` 확인뿐이다.

2026-08-16T05:00Z 이후 운영 DB 조회에서 `price` 실행은 05:06:10Z와 06:04:14Z에 각각 `status=success`, `processedCount=14`와 `8`로 완료되었다. 두 실행 모두 `기존 제휴 링크 20개를 재사용했다`고 기록했고 지원하지 않는 URL은 없었다. 같은 조회 범위에는 `jobType=goldbox` 행이 아직 없으므로, GoldBox 12:00Z 실행 전까지 price 성공만 확정하고 GoldBox 성공은 확정하지 않는다.

## 사용자 확인 가격 CSV·Drive 수입

사용자 확인 가격은 공식 API 가격을 덮어쓰지 않고 `userConfirmedPrices`에 사용자별로 분리 저장한다. 입력 CSV의 필수 열은 `상품명, 확인일시, 확인 가격, 쿠팡 링크`이고 옵션명과 메모는 선택이다. 쿠팡 링크에는 `productId`, `itemId`, `vendorItemId`가 모두 있어야 하며, 사용자가 찜했거나 직접 등록해 활성 상태가 된 동일 옵션 SKU에만 수입된다. 이 수입 경로는 쿠팡 API를 호출하지 않는다.

검색·찜·상품 상세 화면은 공식 API 현재가와 사용자 확인 가격을 별도 출처로 표시한다. 상세 화면의 녹색 차트는 공식 API 가격 이력만 보이며, 사용자 확인 가격은 황금색 개인 이력 목록으로 별도 표시된다. 구현 검증으로 CSV 형식·옵션 SKU·미래 시각·가격 범위 검증, CSV·Drive 수입 경로의 쿠팡 네트워크 미호출, 사용자 소유 범위의 최신 가격 조회를 단위 테스트에 포함했다. 실제 개인 Drive 템플릿 생성 및 가격 행 수입은 배포 후 사용자 흐름으로 검증한다.

## 2026-08-16 GoldBox 강제 실행 시도 결과

`e88e06b0` 이후 04:28Z 기준으로 GoldBox Heartbeat 실행 이력과 운영 `syncRuns`를 조회했으나 신규 실행은 0건이었다. 기존 작업은 활성으로 표시되었지만 마지막 실행 시각이 갱신되지 않아 스케줄 트리거 누락으로 판단했다. 다음 1분 실행으로 임시 cron을 설정했으나 실행 이력이 생성되지 않았고, 중복 실행을 막기 위해 기존 작업을 일시중지한 뒤 임시 작업을 생성해 재시도했음에도 실행되지 않았다. 임시 작업은 삭제했고 기존 작업은 활성 상태로 복원했다. 복원 cron은 `0 0 0,12 * * *`로 명시했으며 다음 예정 시각은 `2026-08-17T00:00:00Z`이다. 강제 실행 시도 중 400·403·500 응답은 관찰되지 않았으나 신규 2xx 콜백과 `syncRuns success`가 없으므로 GoldBox 재개 성공으로 확정하지 않는다. 검증용 쿠팡 API 호출은 만들지 않았다.

## 2026-08-16 GoldBox 최신 버전 실행 성공 검증

최신 배포 버전 `e28f1144`에서 GoldBox Heartbeat task `k3prYjqvg4hu4yavwTDyKj`를 확인했다. 2026-08-16T12:10:21Z에 실행되어 HTTP 200으로 종료되었고, 응답은 `processedCount=29`, `옵션 SKU 19개 중 19개의 딥링크 저장`, `기존 제휴 링크 19개 재사용`, `지원하지 않는 URL 없음`, `수동 대기 링크 0개 활성화`, `Google Drive 상품 스냅샷 148개 updated`를 반환했다. 동일 실행은 운영 DB `syncRuns`에서 `id=1200001`, `jobType=goldbox`, `status=success`, `processedCount=29`, `startedAt=2026-08-16 12:10:25`, `finishedAt=2026-08-16 12:10:31`로 대조됐다. 이전 400 오류 실행 이후 신규 GoldBox 2xx와 성공 로그가 확인되어 GoldBox 재개 성공을 확정한다. 13:34Z의 별도 스케줄 시도는 `schedule status=2, skipped`였으나 오류 응답이 아니며, 정기 작업은 `0 0 0,12 * * *`로 복원되어 다음 실행은 2026-08-17T00:00:00Z이다.

price 작업은 같은 보호 해제 이후 HTTP 200·`syncRuns success` 실행이 확인되었고, pause/resume 및 GoldBox 결과와 함께 재개 성공 증거로 관리한다. 후보 CSV와 사용자 확인 가격 수입은 이 검증에 포함하지 않고 별도 사용자 흐름으로 유지한다.
